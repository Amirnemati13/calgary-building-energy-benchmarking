# Contributing

Changes to parsing, units or evaluation boundaries should include a focused test. Run the checks in the README before opening a pull request. Keep the two notebook editions identical in code; translate narrative separately.

Do not commit downloaded property records, local paths, credentials or generated prediction-level tables. Store new data in a dated local snapshot and record the source hashes. Changes to the reported findings should identify the data version, model settings and evaluation population.

For a methodological change, state the question it addresses and compare against the same eligible observations. Do not choose parameters on the final test set. Preserve unsuccessful comparisons when they are relevant to the research question.

## مشارکت

تغییر در خواندن داده، واحدها یا مرزهای اعتبارسنجی باید آزمون متناسب داشته باشد. پیش از پیشنهاد تغییر، بررسی‌های README را اجرا کنید. کد نوت‌بوک‌های فارسی و انگلیسی باید یکسان بماند.

رکوردهای دریافت‌شده، مسیر شخصی، اطلاعات دسترسی و جدول پیش‌بینی ردیف‌به‌ردیف را منتشر نکنید. نسخهٔ داده، هش منبع، تنظیم مدل و جامعهٔ ارزیابی را برای هر تغییر نتیجه مشخص کنید. پارامترها نباید با مجموعهٔ آزمون نهایی انتخاب شوند.
